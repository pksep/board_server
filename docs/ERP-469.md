# ERP-469 — загрузка и синхронизация доски

Основание изменений — запрос пользователя: догружать задачи без изменения масштаба, показывать подзадачи, доставлять правки другим пользователям и автоматически сохранять существующую задачу. После первоначальной отсрочки второго вида пользователь отдельно задал макет списка, описанный ниже.

## Исследованный сценарий и решение

- Список колонки загружал только корневые задачи. Подзадача в другой колонке зависела от уже загруженной страницы родителя. Существующий `GET /columns/:id/tasks` расширен совместимым режимом `includeSubtasks=true&flatSubtasks=true`: пагинируются сами карточки в фактической колонке. Поиск, исполнители, теги и приоритет применяются до пагинации. Старые запросы сохраняют прежнюю выдачу. `rootTotal` сохраняет отдельный счётчик родительских задач доски; `total` считает все отображаемые карточки.
- События Socket.IO раньше доходили только до пользователей того же экземпляра сервера. Штатные комнаты и gateway используют общий Redis adapter. После восстановления Redis браузеры перечитывают снимок: Pub/Sub не хранит пропущенные события. Права на вход в комнату сохранены.
- Частичные изменения проходят через прежний `TasksService.update`: транзакция, проверка доступа и исполнителей, история изменений, уведомление после commit. Блокировка строки упорядочивает конкурентные записи, а `updatedAt` обновляется также при изменении только исполнителей/тегов. Это позволяет клиенту отвергать устаревшие ответы.
- Клиент сохраняет только изменённые поля, поэтому, например, изменение названия первым пользователем не перезаписывает описание, которое только что изменил второй. Это автосохранение порций ввода, а не совместное редактирование одного текста по символам: для конкурентных записей одного поля сохраняется последняя принятая сервером запись.

Поиск готовой реализации выполнен в tasks/boards/ws, DTO, фильтрах и тестах сервера, а также в `api/board`, `task-board` store, `ProjectPage`, `ModalTask`, `useBoardSocket`, `useTaskDrafts` и общем TiptapEditor клиента. Новые endpoint и альтернативные пути записи не создавались. Переиспользованы существующие update/move/lookup и локальные черновики.

## Развёртывание

Сначала установить серверные зависимости и развернуть сервер, затем клиент ERP-469. Миграция базы не требуется.

- Все экземпляры одного окружения используют один Redis и одинаковый `BOARD_SOCKET_REDIS_KEY`. Независимым окружениям назначаются разные ключи. Если ключ не указан, он строится из адреса/имени PostgreSQL-базы и номера Redis DB. У самого Redis Pub/Sub нет изоляции по номеру DB.
- Redis подключается до открытия API-порта. При его недоступности на старте приложение сообщает об ошибке запуска; во время работы повторное подключение выполняет ioredis.
- Прокси должен поддерживать WebSocket Upgrade на существующем `BOARD_SOCKET_PATH`. Клиент сначала использует WebSocket. Если инфраструктура допускает только HTTP polling, для нескольких экземпляров нужны sticky sessions — закрепление запросов одной сессии за одним экземпляром.
- Подключение браузера начинается после получения серверной сессии доски. После join/reconnect/возврата во вкладку и каждые 30 секунд в видимой вкладке перечитывается актуальное состояние. Порции не превышают 100 карточек, ранее показанный список остаётся видимым до завершения сверки.

Поведение адаптера и требования к балансировщику: [официальная документация Socket.IO](https://socket.io/docs/v4/redis-adapter/).

### Загрузка проектов через localhost

Предоставленная пользователю ссылка localhost:8081 отклонялась OriginMiddleware: локальный start-board-task.ps1 разрешал только 127.0.0.1:8081. Один и тот же GET /board-api/projects возвращал 403 с localhost и 200 с 127.0.0.1. В локальной конфигурации разрешены оба адреса, перезапущен только API доски на 3005. Прикладной код, авторизация и данные не изменены. В test-support.mjs адрес браузера по умолчанию теперь localhost, совпадающий со ссылкой пользователю. Через него прошли 6 interaction-сценариев без runtime-ошибок; отдельно проверены Origin и Referer обоих локальных адресов. Посторонний Origin не получает проекты. Синтаксис скриптов и git diff --check прошли, тестовые данные очищены, окружение работает. Повторная сборка приложения для изменения локальной настройки не требовалась.
