# Задачи на странице «ПЗ по исполнителю»

`GET /api/tasks/by-executor?erpUserId=63&limit=100&offset=0`

Требуется право просмотра производства или производственных заданий ERP.
Назначения читаются независимо от участия текущего читателя в проекте;
`canReadTask` отдельно определяет доступ к обычной карточке задачи.
`erpUserId` — положительный целочисленный ID ERP, сопоставляемый с `users.erp_id`;
внутренний PK Board не используется как запасной идентификатор.
`limit`: 1–100 (по умолчанию 50), `offset`: неотрицательное число (по умолчанию 0).

Ответ имеет формат `PersonalTaskPage`: `{ items: [{ task, projectId, projectPrefix, canReadTask, displayContext }], offset, hasMore }`.
В отличие от личного списка, `task` также содержит HTML `description`.
`offset` в ответе — смещение следующей порции. Порядок: срок готовности, затем ID;
задачи без срока идут последними.

Попадают задачи и подзадачи, назначенные выбранному активному пользователю Board,
если он состоит в проекте. Состав конкретной доски `board.membersIds` не отменяет
назначение: создание и изменение задачи проверяют участие исполнителя в проекте.
Архивные проекты, доски, колонки и задачи, а также колонки с типом
`completed`, `in_review` или `archived` исключаются. Отсутствие связанного
пользователя или назначений даёт пустой список.

`GET /api/tasks/executor-workload?start=2026-11-10T00:00:00Z&end=2026-11-24T00:00:00Z`
использует те же правила назначений. Начало или готовность должны входить
в полуоткрытый период `[start, end)`; готовность может быть на другой странице
календаря. Ответ содержит ERP ID исполнителя, ID и название проекта, даты и
полную норму задачи для каждого исполнителя. Обычные чтение и изменение карточки
сохраняют проверку доступа к проекту.

Необязательный `debtBefore` задаёт начало всего выбранного периода (не позднее
`start`). Он добавляет действующие задачи с более ранним началом даже при
отсутствии обеих дат в текущей странице; `isDebt` указывает на такое назначение.
На следующих страницах передаётся прежний `debtBefore`. Это соответствует
задолженности ПЗ: начало раньше первого дня выбранного периода. Без параметра
сохраняется выборка только по датам страницы, а `isDebt` равен `false`.

Прежние личные списки, счётчики комментариев, назначения, события и расчёты ERP
не меняются. Дополнительная выборка только читает данные Board.

## Календарь загрузки исполнителей

`GET /api/tasks/executor-workload?erpUserIds=18,11,39&start=2026-11-08T19:00:00.000Z&end=2026-11-22T19:00:00.000Z`

Маршрут использует общую область назначений `/tasks/by-executor`: право
планирования ERP, активный исполнитель, участие исполнителя в проекте и
исключение архива каждого уровня. Участие читателя в проекте и исполнителя
в составе конкретной доски не требуется. Необязательный `erpUserIds` — от 1
до 250 положительных целочисленных ID ERP; без него выбираются все исполнители.
Повторные ID и назначения не удваивают результат.

`start` и `end` — ISO 8601, начало включается, конец исключается и должен быть
позже начала; максимальная длина страницы — 31 день. Возвращаются задачи и
подзадачи с положительной нормой времени,
если начало работ или срок готовности попадает в период. Статусы `completed`,
`in_review` и `archived` исключаются; колонки без статуса учитываются.

Ответ — массив `{ executorId, taskId, projectId, projectName, startDate, dueDate,
timeNormMinutes, isDebt }`, где `executorId` — числовой ID ERP. Даты могут быть `null`.
Полная норма каждой задачи относится клиентом отдельно к дню начала и готовности.
При `debtBefore` также возвращаются более ранние действующие задачи, включая
задачи без нормы: они отмечают задолженность без добавления часов на видимые дни.
Смены и расчёты ERP сохраняются. Пустая выборка возвращает `[]`,
неверные параметры — `400`, отсутствие авторизации — `401`.

Маршрут зарегистрирован перед `/tasks/:id`: его имя не преобразуется в ID задачи.
Запрос не изменяет данные, не записывает время и не создаёт события.
