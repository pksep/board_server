# Задачи на странице «ПЗ по исполнителю»

`GET /api/tasks/by-executor?erpUserId=63&limit=100&offset=0`

Авторизация и права чтения проекта совпадают с `/api/tasks/personal`.
`erpUserId` — положительный целочисленный ID ERP, сопоставляемый с `users.erp_id`;
внутренний PK Board не используется как запасной идентификатор.
`limit`: 1–100 (по умолчанию 50), `offset`: неотрицательное число (по умолчанию 0).

Ответ имеет формат `PersonalTaskPage`: `{ items: [{ task, projectId, projectPrefix }], offset, hasMore }`.
В отличие от личного списка, `task` также содержит HTML `description`.
`offset` в ответе — смещение следующей порции. Порядок: срок готовности, затем ID;
задачи без срока идут последними.

Попадают задачи и подзадачи, назначенные выбранному активному пользователю Board,
если он состоит в проекте и в `board.membersIds`. `null` у старых досок означает
наследование состава проекта; пустой массив означает отсутствие участников.
Проект должен быть доступен текущему читателю. Архивные проекты, доски, колонки
и задачи исключаются. Отсутствие связанного пользователя или назначений даёт пустой список.

Прежние личные списки, счётчики комментариев, назначения, события и расчёты ERP
не меняются. Дополнительная выборка только читает данные Board.

## Календарь загрузки исполнителей

`GET /api/tasks/executor-workload?erpUserIds=18,11,39&start=2026-11-08T19:00:00.000Z&end=2026-11-22T19:00:00.000Z`

Маршрут использует общую область назначений `/tasks/by-executor` с теми же
проверками читателя, активного пользователя, состава проекта и доски, а также
архива каждого уровня. `erpUserIds` — от 1 до 250 положительных целочисленных
ID ERP; параметр необязателен. Без него возвращаются все доступные назначения
активных сотрудников с корректным числовым ID ERP, включая сотрудников без
операций ПЗ. Явно переданный пустой список недопустим. Повторные ID и назначения
не удваивают результат.

`start` и `end` — ISO 8601, начало включается, конец исключается и должен быть
позже начала. Возвращаются задачи и подзадачи с положительной нормой времени,
если начало работ или срок готовности попадает в период. Статусы `completed`,
`in_review` и `archived` исключаются; колонки без статуса учитываются.

`debtBefore` — необязательная граница ISO 8601. При её передаче дополнительно
возвращаются незавершённые задачи с началом работ строго раньше границы,
в том числе без нормы времени. Это соответствует задолженности операций ПЗ
по дате начала работ. В каждой записи появляется `isDebt`; отсутствие начала
работ даёт `false`. При догрузке дней клиент сохраняет исходную границу.
Без `debtBefore` прежний отбор только положительных норм в периоде сохраняется.

Пример запроса из `WorkloadBody.vue`:

`GET /api/tasks/executor-workload?start=2026-11-11T19:00:00.000Z&end=2026-11-25T19:00:00.000Z&debtBefore=2026-11-11T19:00:00.000Z`

Ответ — массив `{ executorId, taskId, projectId, projectName, startDate, dueDate,
timeNormMinutes, isDebt? }`, где `executorId` — числовой ID ERP. Даты и норма
времени задолженной задачи могут быть `null`.
Полная норма каждой задачи относится клиентом отдельно к дню начала и готовности;
смены, задолженность и расчёты ERP сохраняются. Пустая выборка возвращает `[]`,
неверные параметры — `400`, отсутствие авторизации — `401`.

Маршрут зарегистрирован перед `/tasks/:id`: его имя не преобразуется в ID задачи.
Запрос не изменяет данные, не записывает время и не создаёт события.
