# Время сотрудника и самостоятельные записи

По просьбе пользователя форма фактического времени позволяет выбрать сотрудника. По умолчанию время по-прежнему учитывается текущему пользователю. В задаче другой сотрудник должен быть активным участником проекта либо его владельцем. Проверка доступа записывающего пользователя к задаче сохранена.

Кнопка «+» в учёте времени создаёт самостоятельную запись без задачи. Используется тот же `TasksService.createTimeEntry`, та же таблица, ограничения длительности и комментария, транзакция и серверная дата создания. Фиктивные задачи, проекты и отметки результатов работ не создаются.

- `user_id` относится к сотруднику, которому учитывается время. Существующее поле `actor` в ответе сохраняет представление этого сотрудника.
- `created_by_id` хранит фактического автора из проверенной сессии. Его нельзя передать клиентом.
- Старые клиенты без `userId` продолжают записывать время себе. Старые записи и вставки получают автора из `user_id`.
- `GET /time-entries` читает самостоятельные записи за полуоткрытый период, не более 32 дней на запрос, с курсором `beforeId`.
- `POST /time-entries` создаёт самостоятельную запись. Нужны оба права ERP: `general.time-tracking:view` и `general.time-tracking:create`. Просмотр требует только первого права. Доступ к проектам для этого маршрута не требуется.
- Отчёт `/tasks/time-report` по-прежнему ограничен доступными проектами и не включает самостоятельное время.

Перед обновлением сервера применить `20261113120000-standalone-time-entries.js`. Миграция сохраняет записи, поддерживает старый формат вставки и допускает повторный запуск. Откат отказывается уничтожать самостоятельные записи или отдельное авторство.

Полный сценарий исследован от `ModalTaskTime` и `TaskTime` через существующий Board API до SQL и общего серверного экспорта ERP. Изменение основано на прямом запросе пользователя о выборе сотрудника и подтверждении «Отдельная запись без задачи». Проверки покрывают сохранение и повторное чтение, выбор коллеги, прежний выбор себя, заблокированных пользователей, границы периода, курсор, права, подмену автора и сохранность данных при миграции и откате.
